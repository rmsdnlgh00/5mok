# 재료맨틀 (food-mantle)

꼬맨틀/세만틀 스타일의 "재료로 음식 맞추기" 게임. 재료를 입력하면 오늘의 정답 음식과의
의미적 유사도를 0~100 점수로 알려주고, 음식 이름을 직접 맞히면 승리합니다.

**API 키가 필요 없습니다.** 임베딩은 로컬 모델(Transformers.js)로 계산하며, 배포된 서버는
미리 계산해둔 값만 읽습니다.

## 동작 원리

1. `data/dishes.json` 에 음식별 실제 재료 목록을, `data/extra-ingredients.json` 에 정답과
   무관한 일반 재료들을 정의해둡니다. 둘을 합친 것이 "사전(vocabulary)"입니다.
2. `npm run precompute` 를 실행하면:
   - 사전 전체를 로컬 임베딩 모델로 벡터화해 `data/vocab-embeddings.json` 에 저장합니다.
   - 음식마다 자기 재료 임베딩의 평균("프로필 벡터")을 구합니다.
   - 사전 전체 단어를 각 음식 프로필과의 코사인 유사도 순으로 정렬해
     `data/rankings/<dishId>.json` 에 저장합니다.
3. 서비스가 실행되는 동안에는 **미리 계산된 값만 읽습니다.** 임베딩 모델은 서버에 올리지
   않기 때문에(용량 250MB 제한, 콜드스타트) 런타임 연산이 사실상 0입니다.
4. 오늘의 정답 음식은 **KST 날짜 문자열을 해시**해서 결정하기 때문에, 별도 DB 없이도
   모든 사용자가 하루 동안 같은 문제를 풉니다(자정에 자동으로 바뀜).

### 입력에 대한 4가지 응답

| 입력 | 응답 |
| --- | --- |
| 정답 음식 이름/별칭 | 승리 |
| 사전에 있는 재료 | 0~100 점수 + 사전 내 순위 (정답의 실제 재료면 "재료 일치" 표시) |
| 다른 음식 이름 | "오늘의 정답이 아니에요" |
| 사전에 없는 단어 | "아직 사전에 없는 재료예요" |

마지막 경우를 줄이려면 `data/extra-ingredients.json` 에 재료를 추가하고 precompute를
다시 돌리면 됩니다.

## 임베딩 모델

기본값은 `Xenova/multilingual-e5-base` (q8, 768차원)입니다. `data/dishes.json` 의 재료로
"각 음식의 자기 재료가 사전 전체에서 몇 위에 오는가"를 측정해 고른 값입니다(낮을수록 좋음):

| 모델 | 자기 재료 평균순위 (/44) |
| --- | --- |
| **multilingual-e5-base (q8)** | **4.68** |
| multilingual-e5-small (fp32) | 5.20 |
| LaBSE (q8) | 10.72 |
| paraphrase-multilingual-MiniLM-L12-v2 | 20.56 (사실상 무작위) |

e5 계열은 학습 때 쓰인 `query: ` 프리픽스를 붙여야 품질이 나오므로 `lib/embed.ts` 에서
모든 입력에 동일하게 적용합니다.

> ⚠️ 모델을 바꾸면 벡터 공간이 완전히 달라집니다. `EMBEDDING_MODEL` 을 변경했다면 반드시
> `npm run precompute` 를 다시 실행하세요. 섞어 쓰면 유사도가 무의미한 값이 됩니다.

## 로컬 실행

```bash
npm install
npm run precompute   # 최초 1회는 모델 다운로드(수백 MB)로 수 분 소요, 이후 캐시됨
npm run dev
```

`.env.local` 은 없어도 동작합니다. 모델을 바꾸고 싶을 때만 `.env.example` 을 참고하세요.

`npm run precompute` 는 **`data/dishes.json` 이나 `data/extra-ingredients.json` 을 바꿀
때마다** 다시 실행해야 합니다.

## Vercel 배포

1. GitHub에 푸시 후 Vercel에서 저장소 import
2. **환경변수 설정 불필요** (API 키를 쓰지 않음)
3. `data/rankings/*.json` 과 `data/vocab-embeddings.json` 은 **로컬에서 미리 생성해서
   같이 커밋**하세요. Vercel 빌드 중에는 precompute를 실행하지 않습니다 — 임베딩 모델을
   빌드 환경에 내려받으면 느리고, 서버리스 번들 용량 제한에도 걸립니다.
4. 배포 후 재료 데이터를 바꾸면: 로컬에서 `npm run precompute` → 커밋 → 다시 배포.

## 음식 추가/수정하기

`data/dishes.json` 에 아래 형식으로 항목을 추가하고 `npm run precompute` 를 다시
실행하면 됩니다.

```json
{
  "id": "unique-id",
  "name": "음식 이름",
  "aliases": ["다른 이름(선택)"],
  "ingredients": ["재료1", "재료2", "재료3"]
}
```

## 지금 버전에서 단순화한 부분 (다음에 개선하면 좋은 것들)

- **음식 15개 + 재료 사전 248단어**로 시작 구성만 잡아뒀습니다. 음식을 늘릴수록 게임이
  풍부해지고, 재료별 "핵심 재료 vs 부재료" 가중치를 주는 것도 고려해볼 만합니다.
- 소형 다국어 모델이라 한국어 단어 유사도에 가끔 엉뚱한 결과가 섞입니다(예: 한자어 음절을
  공유하는 "대추"와 "고추"를 가깝게 봄). 음식/재료 수를 늘리거나 더 큰 모델을 쓰면 완화됩니다.
- 오탈자/유사어 처리(예: "고추장" vs "고추장양념")가 없습니다. 필요하면 사전에
  동의어 매핑 테이블을 추가하는 게 좋습니다.
- 하루 지난 정답을 보여주는 "어제의 정답" 기능, 공유하기(결과 이미지) 같은 건
  포함하지 않았습니다.
- 현재는 세션 저장이 없어서 새로고침하면 시도 기록이 날아갑니다. 필요하면
  localStorage에 오늘 날짜 기준으로 저장하면 됩니다.
